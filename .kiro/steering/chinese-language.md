# 中文语言规则

## 核心原则

**所有与用户的交互、文档编写和代码注释都必须使用中文。**

## 适用范围

### 1. 用户交互
- 所有回复都使用中文
- 解释技术概念时使用中文
- 提供建议和指导时使用中文
- 错误信息和警告使用中文

### 2. 文档编写
- README 文件使用中文
- 技术文档使用中文
- API 文档使用中文
- 注释和说明使用中文
- Commit 消息使用中文（但保留 Conventional Commits 前缀，如 `feat:`, `fix:` 等）

### 3. 代码注释
- 所有代码注释使用中文
- JSDoc/TSDoc 注释使用中文
- TODO/FIXME 标记使用中文
- 函数和类的说明使用中文

### 4. 代码命名（保持英文）
- 变量名、函数名、类名等标识符仍使用英文（遵循编程规范）
- 常量名使用英文
- 文件名使用英文

## 示例

### 正确的代码注释风格：

```typescript
/**
 * 用户认证服务
 * 负责处理用户登录、注销和权限验证
 */
class AuthService {
  /**
   * 验证用户凭证
   * @param username - 用户名
   * @param password - 密码
   * @returns 认证令牌
   */
  async authenticate(username: string, password: string): Promise<string> {
    // 检查用户名和密码是否为空
    if (!username || !password) {
      throw new Error('用户名和密码不能为空')
    }
    
    // TODO: 实现实际的认证逻辑
    return 'token'
  }
}
```

### 正确的 Commit 消息：

```
feat: 添加用户认证功能
fix: 修复登录页面的表单验证问题
docs: 更新 API 文档
refactor: 重构用户服务模块
```

### 正确的文档风格：

```markdown
# 用户管理模块

## 功能概述

本模块提供完整的用户管理功能，包括：

- 用户注册和登录
- 权限管理
- 个人资料编辑

## 使用方法

1. 导入用户服务
2. 调用相应的 API
3. 处理返回结果
```

## 例外情况

以下情况可以使用英文：

1. **代码标识符**：变量名、函数名、类名等必须使用英文
2. **技术术语**：某些专有技术术语可以保留英文（如 API、HTTP、JSON 等）
3. **第三方库**：引用第三方库的名称和 API 时使用原始英文
4. **配置文件**：某些配置文件的键名需要使用英文（如 package.json）

## 响应模板

当完成任务时，使用以下格式：

```
✅ 任务完成

我已经完成了以下工作：
1. [具体完成的内容]
2. [具体完成的内容]

📝 说明：
[详细的说明和注意事项]

🔍 验证步骤：
1. [如何验证结果]
2. [如何测试功能]
```
