## 贡献流程

Cherry Studio 欢迎所有开发者的贡献。贡献方式包括代码贡献、Bug 修复、问题维护、产品设计、文档编写、社区维护和推广使用。在开始贡献之前，请确保您已阅读[行为准则](CODE_OF_CONDUCT.md)和[许可证](LICENSE)。

对于新贡献者，建议从标记为 `good-first-issue`、`help-wanted` 或 `kind/bug` 的问题开始。所有功能都必须有相应的测试，包括单元测试和功能测试。自动化测试会在组织成员创建的拉取请求上触发，新贡献者的请求需要组织成员添加 `/ok-to-test` 标签后才会触发测试。

建议将尚未完成或需要讨论的拉取请求创建为草稿（draft pull requests），这样可以节省 CI 资源，并让社区了解该请求尚未准备好审查。审查者将在您将草稿标记为“准备就绪”后被分配。

所有贡献者必须通过签署提交（sign-off commits）来确认他们有权合法地为项目贡献代码。这可以通过以下命令完成：
```
git commit --signoff -m "您的提交信息"
```

在提交拉取请求前，可以先联系开发者进行讨论或寻求帮助。目前，项目暂时不接受会改变 Redux 数据模型或 IndexedDB 模式的功能拉取请求，此类请求将被关闭。此限制是暂时的，预计在 `v2.0.0` 版本发布时解除。

## 开发环境设置

要设置 Cherry Studio 的开发环境，您需要安装 Node.js（版本 >=22.0.0）和 Yarn 包管理器。项目使用 Yarn 4.9.1 进行依赖管理。安装依赖后，您可以使用以下命令启动开发服务器：

- `yarn dev`: 启动开发模式
- `yarn start`: 预览构建后的应用
- `yarn debug`: 以调试模式启动应用

项目使用 Electron-Vite 作为构建工具，支持主进程、预加载脚本和渲染进程的独立配置。TypeScript 配置分为 `tsconfig.node.json`（用于主进程和脚本）和 `tsconfig.web.json`（用于渲染进程），通过 `tsconfig.json` 进行引用。

项目还包含一些必要的二进制工具，如 UV 和 Bun，这些工具会在用户首次使用相关功能时自动安装。`scripts/utils.js` 文件中包含了下载和解压 npm 包的工具函数，用于在运行时安装这些依赖。

## 代码风格与规范

Cherry Studio 使用 ESLint 进行代码检查，配置文件为 `eslint.config.mjs`。项目遵循一系列严格的代码规范，以确保代码质量和一致性。

主要的 ESLint 配置包括：
- 使用 `@electron-toolkit/eslint-config-ts` 作为基础配置
- 使用 `@eslint-react/eslint-plugin` 进行 React 代码检查
- 使用 `eslint-plugin-simple-import-sort` 对导入语句进行排序
- 使用 `eslint-plugin-unused-imports` 检测未使用的导入
- 使用 `eslint-plugin-import-zod` 推荐使用 Zod 命名空间

项目还定义了一些自定义规则，例如禁止在 `t()` 函数中使用模板字符串，以避免不可预测的渲染结果。此外，项目禁止直接使用 `console` 语句，要求统一使用 `LoggerService` 进行日志记录。

代码格式化由 Biome 工具完成，可以通过 `yarn format` 命令执行。`lint-staged` 配置确保在提交代码前自动格式化和检查代码。

## 构建与打包流程

Cherry Studio 使用 Electron Builder 进行应用的构建和打包。构建流程由 `electron.vite.config.ts` 配置，分为主进程、预加载脚本和渲染进程三个部分。

构建命令包括：
- `yarn build`: 执行类型检查并构建应用
- `yarn build:unpack`: 构建为可执行目录
- `yarn build:win`, `yarn build:mac`, `yarn build:linux`: 分别构建 Windows、macOS 和 Linux 平台的安装包

打包配置在 `electron-builder.yml` 文件中定义。该文件指定了应用 ID、产品名称、协议处理、文件包含/排除规则、平台特定配置（如 Windows 的 NSIS 安装程序、macOS 的 DMG 镜像、Linux 的 AppImage 等）以及发布配置。

构建过程中会执行 `before-pack.js` 和 `after-pack.js` 脚本，分别在打包前后进行处理。对于 macOS 应用，还配置了 `notarize.js` 脚本进行公证。

## 调试技巧

Cherry Studio 提供了多种调试工具和技巧来帮助开发者定位和解决问题。

在开发模式下，可以使用 `yarn debug` 命令启动应用，并通过 `--inspect` 参数启用 Chrome DevTools 进行调试。渲染进程的代码可以通过 Electron DevTools 查看和调试。

项目使用 `LoggerService` 进行统一的日志记录，所有日志都会被写入文件，便于问题排查。开发者可以通过 `src/main/utils/index.ts` 中的 `makeSureDirExists` 函数确保日志目录存在。

对于主进程和渲染进程的分离式架构，可以分别使用不同的测试配置。`vitest.config.ts` 文件中定义了针对主进程（node 环境）和渲染进程（jsdom 环境）的独立测试项目。端到端测试使用 Playwright，配置在 `playwright.config.ts` 中，可以模拟用户操作并验证应用行为。

## 代码提交最佳实践

为了保持代码库的整洁和可维护性，Cherry Studio 遵循一系列代码提交的最佳实践。

提交信息应清晰、简洁地描述更改内容。所有提交都必须使用 `--signoff` 参数进行签署，以确认贡献者遵守项目许可证。分支管理遵循标准的 Git 工作流：从主分支创建特性分支，完成开发后提交拉取请求。

代码提交前，应确保通过所有测试和代码检查。`package.json` 中的 `prepare` 脚本会自动设置 Git 钩子，确保在提交前执行必要的检查。`lint-staged` 配置会自动格式化和检查暂存区的文件。

对于涉及环境变量的操作，应使用 `src/main/utils/shell-env.ts` 中的 `appendCherryBinToPath` 函数来确保 Cherry Studio 的二进制目录被正确添加到 PATH 环境变量中，同时避免路径重复。
